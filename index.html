Interfacing a Gyroscope (MPU-6050) and Bluetooth (HC-05) with the ATtiny85

1. Introduction and objectives

The ATtiny85 is an 8-bit AVR with 8 KB flash, 512 B SRAM, 512 B EEPROM and six pins (PB0–PB5). It has no hardware UART or TWI; its USI (Universal Serial Interface) shifts bits for software-assisted I²C or SPI. A MEMS gyroscope (here the InvenSense MPU-6050: 3-axis gyro + 3-axis accelerometer) reports angular rate over I²C. A Bluetooth SPP module (HC-05/HC-06) is a transparent wireless UART bridge. Together they make a tiny wireless motion sensor.

Principle: the MCU is I²C master, reads rate registers at a fixed period, scales them to physical units, optionally fuses them with accelerometer data, and prints a packet on a bit-banged serial port that the Bluetooth module relays to a phone or PC.

Prerequisites

I²C (START/STOP, ACK, open-drain, pull-ups), UART 8N1 framing, two's-complement numbers, voltage dividers, AVR fuses.

3. Working principle

  1. Clock: factory fuses give 8 MHz RC ÷8 = 1 MHz. Program fuses for 8 MHz so software UART timing at 9600 baud is reliable.
  2. Wake the gyro: MPU-6050 powers up asleep (PWR_MGMT_1 = 0x40). Write 0x00 to register 0x6B.
  3. Read: START, 0x68+W, register 0x43, repeated START, 0x68+R, 6 bytes (GYRO_XOUT_H…ZOUT_L), STOP. Each pair is a signed 16-bit value, high byte first.
  4. Scale: ω = raw ÷ sensitivity (default ±250 °/s → 131).
  5. Transmit: format a packet and send via SoftwareSerial on PB3. HC-05 radiates it; its received bytes arrive on PB4.

DC vs AC (signal) view

DC: 3.3 V sensor supply, I²C idle-high via pull-ups, logic levels must match. AC/dynamic: 100 kHz I²C clock edges, 9600 baud serial bits (104.17 µs each).

Starter code (ATtinyCore, Arduino IDE)

#include <TinyWireM.h>
#include <SoftwareSerial.h>
SoftwareSerial bt(4, 3);            // RX=PB4, TX=PB3
void setup(){ bt.begin(9600); TinyWireM.begin();
  TinyWireM.beginTransmission(0x68); TinyWireM.write(0x6B); TinyWireM.write(0); TinyWireM.endTransmission(); }
void loop(){
  TinyWireM.beginTransmission(0x68); TinyWireM.write(0x43); TinyWireM.endTransmission();
  TinyWireM.requestFrom(0x68, 6);
  int16_t g[3];
  for(byte i=0;i<3;i++){ int16_t h=TinyWireM.read(); g[i]=(h<<8)|TinyWireM.read(); }
  bt.print(g[0]/131.0,1); bt.print(','); bt.print(g[1]/131.0,1); bt.print(','); bt.println(g[2]/131.0,1);
  delay(20); }
Limitations: SoftwareSerial disables interrupts during bytes, so I²C timing and reception can be disturbed; RX and TX are not simultaneous; float printing costs flash on 8 KB; ATtiny85 has no hardware multiplier, so use fixed-point for heavy fusion.

Misconceptions

  • “Integrating gyro rate gives absolute angle.” It gives angle change; bias makes it drift.
  • “HC-05 pins are 5 V tolerant.” RXD is 3.3 V logic.
  • “PB5 is a normal pin.” Using it as I/O disables reset/ISP.

5. Equations

Scaling

ω (°/s) = Nraw / Sg,   Sg = 131, 65.5, 32.8, 16.4 LSB/(°/s) for ±250/500/1000/2000 °/s

Nraw: signed 16-bit count. Full-scale ÷ 32768 gives the same numbers (250/32768 → 131.07 LSB per °/s). Accelerometer: a (g) = N/16384 at ±2 g.

Angle integration

θk = θk−1 + ωk·Δt  ;  drift = b·t

b = bias in °/s, Δt in s. A constant bias integrates into linear error (limiting case: b=0 gives ideal tracking, but noise still gives random walk).

Complementary filter

θk = α(θk−1 + ωkΔt) + (1−α)θacc,   α = τ/(τ+Δt)

High-pass on the gyro path, low-pass on the accelerometer path. τ is the crossover time constant (s). Valid when the sensor is not under sustained linear acceleration. θacc = atan2(ay, az).

Serial timing

tbyte = 10/B  ;  fmax = B/(10·Nbytes)

B in baud, 10 = start + 8 data + stop. Meaning: link-limited packet rate. For I²C: t ≈ (9·Nbytes on bus)/fSCL.

Level shifter

Vout = Vin·R2/(R1+R2)

Unloaded divider; valid because the HC-05 RXD input current is negligible.

6. Solved problems

P1 (Easy): scaling

Gyro at ±250 °/s outputs raw = 262. Find ω. Formula ω = N/Sg. ω = 262 / 131 LSB/(°/s) = 2 °/s. Interpretation: the board is rotating slowly, about one turn per 3 minutes.

P2 (Moderate): integration

±500 °/s range, raw = −6550, Δt = 20 ms. Sg=65.5, ω = −6550/65.5 = −100 °/s. Δθ = −100 × 0.020 s = −2° per sample. Over 50 samples (1 s) = −100°. Interpretation: the sign gives rotation direction.

P3 (GATE style): bandwidth

Packet = 2 header + 12 data + 1 checksum = 15 bytes, 9600 baud 8N1. Bits/packet = 15×10 = 150. fmax = 9600/150 = 64 packets/s (15.6 ms each). Practical rates are lower due to I²C read time (≈0.85 ms for 6 bytes at 100 kHz) and disabled interrupts. Shortcut: bytes/s = baud/10.

8. Interview preparation

Industry perspective

Wearables, drones and robots use the same chain (MEMS IMU → low-power MCU → wireless link). Interviewers test bus-level debugging, power/level compatibility, timing budgets and sensor-fusion intuition more than library usage.

Troubleshooting

  • All zeros: sleep bit not cleared.
  • No ACK: wrong address, no pull-ups, SDA/SCL swapped.
  • Garbage on phone: baud mismatch or MCU still at 1 MHz.
  • Cannot reflash: PB5 used as I/O.
Memory aid: “Zero the sleep, scale by the range, divide baud by ten.”
